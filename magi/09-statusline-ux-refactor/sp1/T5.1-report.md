## 定案

**存取形式**：`t(locale: Locale): Messages` ——回整包字典（非逐 key 查表）。兩語言字典 `zhHant`／`en` 皆顯式標型 `const … : Messages`，這是 arity／placeholder parity 的 typecheck 罩門核心：任一字典漏一個函式鍵、或函式鍵簽章（參數數量／型別）與介面不符，`npm run typecheck` 即紅——已用 `npm run typecheck` 實測乾淨通過（見下方測試節），介面＋雙字典皆滿足契約。

**Messages 介面結構**：

- `segments: Record<SegmentId, { label: string; ariaText: string }>`——型別直接 `import type { SegmentId } from './segments.js'`（型別導入，零執行期依賴；segments.ts 本身零 DOM，純目錄模組，安全 import）。用 `Record<SegmentId, …>` 而非手寫 30 條 key 的好處：兩字典任一漏段、或段 id 拼錯，**編譯期**就過不了，「key 集合相等」的機械保證下推至型別系統，執行期 meta 案只需再做一次深度比對即可（防 `Record` 型別本身被繞過的邊角案，如 `as` 斷言）。
- `resetAriaWord: string`——resolve.ts:429 `suffix.replace('↺', '重置')` 的「重置」代換詞 i18n 化。
- `rowSelect.rowOption(n)` / `rowOptionPending(n)`——row-select.ts:68-73「第 N 列」／「第 N 列（新列）」。
- `announce.move` / `catalogAdd` / `removed` / `rowDeleted`——四句形對應 row-groups.ts `formatMoveAnnouncement`、main.ts `announceSegmentLanded`('catalog-add' 分支)、`removeSegment`、`performRowDeletion`。全部建模為函式鍵（非樣板字串＋事後插槽比對），插值 arity 由 TS 簽章鎖死。

**純度**：`messages.ts` 僅 `import type { SegmentId } from './segments.js'`（type-only，編譯後清除），無其他 import；不讀 `document`/`window`/`localStorage`。`messages.test.ts` 本身在本專案 vitest 預設環境（node，`vite.config.ts` 無 `test.environment` 覆寫；`.dom.test.ts` 才用 `// @vitest-environment jsdom` pragma 另開）下全數通過，即為「零 DOM」的自證——若 messages.ts 意外拉入 DOM 相依模組，node 環境 import 階段就會拋錯，此測試檔任何一案都過不了。

## en 初稿品質自評與待打磨清單

**品質自評**：30 段 label／ariaText 依團隊給定慣例直譯（`model→Model`、`目前目錄→Current dir`、`上下文剩餘→Context remaining`、`7 日限額重置倒數→7-day limit reset countdown` 等），語意清楚、無明顯歧義；四句 `announce` 模板與兩句 `rowSelect` 模板為機械英譯（保留原文語序與資訊順序），文法正確但偏直譯腔（如 `moved to row N position M (of K)`），非道地英文文案打磨。`pr` 段刻意 label／ariaText 不同形（`PR` / `Pull request`）——沿用 zh-Hant「PR」／「拉取請求」的既有慣例（label 用官方縮寫、ariaText 用全稱），非翻譯疏漏。

**待 T5.5 打磨清單**：

1. `announce.rowDeleted` 英文 `"N segment(s) returned to catalog"` 的 `(s)` 為機械複數處理，非道地英文（`1 segment(s)` 讀起來生硬）——T5.5 可視實際 i18n 慣例（如複數形分流或用 "segment" 恆定單數）調整，惟需注意此舉會改變 arity（若改為需要複數判斷邏輯，函式簽章或內部邏輯需相應調整，介面 `(row, count) => string` 本身不必變）。
2. `git-dirty` 的 ariaText 譯為 `Uncommitted changes`（非逐字 `Git dirty flag` 的字面對應）——刻意選擇更口語的 SR 表達，符合 zh-Hant「未提交變更」的語意，但與同段 label `Git dirty flag` 用詞不同源，T5.5 打磨時可評估是否統一措辭風格。
3. 兩語言字典目前均未經真機 screen reader 或 native speaker 校閱——依 PLAN 分工，真機 checklist 抽查把關為 T5.5 職責範圍，本階段僅交付「結構正確＋語意合理」的初稿。
4. `announce.move`／`catalogAdd` 英文版 "position M (of K)" 的 "of" 用法可考慮改為更常見的 "M of K" 或 "position M/K" 等慣用格式，本階段維持直譯以求與 zh-Hant 版本結構一一對應，便於日後调整時對照。
