## seam 簽章與放置

```ts
// tools/statusline-builder/enable-into-target.ts（新純模組）
export function planEnableIntoTarget(
  slots: readonly RowSlot[],
  segments: readonly PlanSegmentInput[],
  movedId: string,
  target: DropTarget,
): SegmentMovePlan
```

**放新純模組（非 main.ts export、非擴充 planSegmentMove），理由：**
1. 決策核心**完全純函式化**（輸入 slots/segments/movedId/target → 輸出
   `SegmentMovePlan`），零 DOM、零模組狀態——fits row-slots.ts／row-groups.ts
   ／row-separators.ts「可測邏輯外抽 DOM-free 模組」既有慣例，node 可直測，
   毋須 boot 整頁。
2. **語意本質不同於 `planSegmentMove`**：後者輸入假設段已啟用（`sourceRow`＝
   現列），其步驟 1（來源列＋`srcDrains`）／2（`srcSlot`）／4（來源耗盡
   `convertRealToPending`）皆環繞來源列。停用段無來源列——enable-into-target
   是**純插入**：無來源 drain、無來源位縮併、`bumpIds` 只受 target 側影響。
   故只取 `planSegmentMove` 的步驟 3（落點解析＋pending 側 bump 收集＋
   consume），刻意不含 1/2/4。
3. row-slots.ts 在禁改清單，且委派文明禁「wrapper 先物化虛擬來源」（會重演
   C1 的 clamp/drain 中間態）——決策層必須一步到位，故獨立成新檔；型別
   （`DropTarget`／`SegmentMovePlan`／`PlanSegmentInput`）與位映射
   （`realIndexOfSlot`／`consumePendingSlot`）皆自 row-slots.ts import，
   單一事實來源、不重複宣告。

## commitSegmentMove 整合（關鍵決策）

`commitSegmentMove` 改 `export`（供 seam 整合直測驅動；drop handler 是 T3.3），
開頭新增停用段分支：`movedSeg !== undefined && !movedSeg.enabled` → 委派新
函式 `commitEnableIntoTarget`，`return`；已啟用段走原路徑（movedSeg 提前
fetch，`planSegmentMove` 不依賴該變數，**行為零變**）。

`commitEnableIntoTarget(movedId, target, beforeId)` 順序：
1. `markSegmentEnabledDeferred(movedId)`（T3.1 積木：只設 `enabled=true`，
   不 clamp／不動 slots／不 commit——row 落點交步驟 2 一步定，杜絕 clamp 中間態）。
2. `planEnableIntoTarget(rowSlots, config.segments, movedId, target)`（seam；
   slotIndex 於同一同步事件內取用，不跨 relayout）。
3. 套 `bumpIds`（`row +1` 原地 mutate）／`rowSlots = plan.nextSlots`／
   `rowSeparators`——復用既有 `computeRowSeparatorsAfterMove`，但**純插入＝
   `srcDrains` 恆傳 `false`**（無來源列），故只做 pending 側 `insertNullAtReal`、
   絕不觸發來源 `removeRealAt`；`sourceRow` 於 `srcDrains=false` 時不被讀取
   （其 `sameRowInsert` 閘），傳 `0` 佔位。
4. `performCrossRowMove(movedId, plan.targetRow, beforeId)`——**唯一一次**
   `commitConfig`（於其內）＋播報（暫用既有「移至第 N 列第 M 位」文案）＋
   `seg.row` 寫回 target。
5. **唯一 commit 後**補跑 `syncSegmentEnabledUi(movedId, true)`＋
   `syncFgOverrideDisabled()`（round 2 收口，防 I4b 重演）。

**單次 commit 保證**：markSegmentEnabledDeferred 不 commit、兩個 UI 同步不
commit，唯一 commit 落在 performCrossRowMove 內——jsdom 以 `Storage.prototype.
setItem` spy 計數，enable 操作恰 1 次（測實證）。

## 測試（tools/statusline-builder/enable-into-target.dom.test.ts，14 案）

- **(1) seam 直測**（planEnableIntoTarget 直呼，DOM-free，3 案）：
  情境 1 空清單唯一 pending → `nextSlots=[real]`／`targetRow=0`／`bumpIds=[]`
  ＋不 mutate 輸入；情境 2 中間 pending → `targetRow=1`／`bumpIds=[cost,model]`
  ／`nextSlots=[real,real,real]`；情境 3 真實列 → `targetRow=N`／無 bump／
  slots 不動。
- **(2) 整合**（boot＋`mod.commitSegmentMove` 驅動停用段分支，5 描述）：
  情境 1 空清單拖入唯一 pending（add-row 得 `[pending]`）→ `rowSlots=[real]`／
  無孤兒 pending／`row=0`／**恰 commit 一次**＋checkbox 勾選／退隱藏池；
  情境 2 中間 pending 物化（先 rowSelect 併列耗盡得 `[real,pending,real]`）→
  3 真實列／git-branch 落列 1／cost・model bump 至列 2／`rowSeparators=[·,null,~]`
  （跟列走）／恰 commit 一次；情境 3 真實列 beforeId=cost → `row1=[model,
  git-branch,cost]`／slots 不變／恰 commit 一次；情境 4 **I4b 不重演**（powerline
  ＋bar 百分比段 context-remaining 停用中→拖入 row0：前置驗 picker 尚未
  disabled〔enabled=false 未觸發閘，正是過期態根因〕，enable 後 fgOverride
  fieldset `disabled=true`＋checkbox 勾選）；情境 5 **已啟用段零變**顯式回歸
  （移動 enabled 的 cost 至 row0，走原 enabled 路徑、非分支：cost 落 row0／
  model 留 row1／2 列不變／恰 commit 一次）。

非空洞性（logical）：無分支時情境 1 之 git-branch 仍 disabled → 0 真實列＋
`enabled:false`，斷言即紅；無步驟 5 之 syncFgOverrideDisabled 則情境 4
fieldset 停 `disabled:false`，斷言即紅。
