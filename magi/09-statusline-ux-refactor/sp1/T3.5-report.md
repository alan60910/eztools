# T3.5 — data-testid 上錨＋e2e 5 案改造

## 定案

**data-testid 新慣例落地**（index.html 模板＋main.ts 動態維護點）：依「動到哪錨到哪」原則，錨定 e2e 5 案實際消費的節點＋T3.3 新增的目錄項拖曳源，共六類：

1. **列群組容器**（`segment-row-group-template` 根 `<section>`）：`data-testid="row-group"` ＋ `data-row-index`（顯示編號，非 0-index）。`data-row-index` 於 `createRowGroupContainer` 建立時先烙印初值（`index+1`，與同函式內 heading 文字同源），容器存活期間由 `refreshRowNumbering`（`layoutSegmentContainers` 每次呼叫之收尾步驟，見其文件）依 `slotIndexOfRealRow(rowSlots, i)+1` 同步——與 heading 文字**同一組數值**，只是不透過 textContent 暴露，e2e 讀 `dataset.rowIndex` 即得，不必比對 i18n 可見文字。
2. **段列 `<li>`**（`segment-row-template`）：`data-testid="segment-row"`，與既有 `data-segment-id` 併用（後者本身即穩定屬性、非結構路徑，但為統一 e2e 一律走 `data-testid` 慣例，兩者組合成選擇器 `[data-testid="segment-row"][data-segment-id="x"]`）。
3. **拖曳握把**（`.segment-row__grip`）：`data-testid="segment-grip"`。
4. **列指派 select**（`.segment-row__row-select`）：`data-testid="row-select"`。
5. **暫存空列容器**（`segment-pending-row-template` 根 `<div>`）：`data-testid="pending-row-group"` ＋ `data-row-index`（該 pending slot 顯示編號，`renderPendingRowContainers` 重繪時寫入，與 heading 文字同源）；其刪除鈕：`data-testid="pending-row-delete"`。
6. **左欄目錄項**（`catalog-item-template` 根 `<li>`，T3.3 新拖曳源，T3.3 交接明確指出「尚未上 data-testid」）：`data-testid="catalog-item"`——本次 5 案未直接消費（拖曳來源皆中欄），但作為「M3 新增互動節點」隨 T3.5 一併補上，避免 T6.1（e2e 新增「目錄拖入指定列」案）屆時又要回頭補模板。

**額外一併上錨**（非清單列舉六類之一，但為快照擴充服務）：列群組的逐列分隔符 preset select（`.segment-row-group__separator-preset`，T1.7 新增控件）補 `data-testid="row-separator-preset"`——e2e 快照現在會讀取它。

### 快照攜帶 separator 狀態的做法：讀 DOM 控件值 vs 重算 localStorage config（決策記錄）

**選擇：直接讀 DOM 控件（`row-separator-preset` select 的 `value`）**，非重新推導 `localStorage` 內 `config.rowSeparators` 並複刻 `main.ts refreshRowSeparatorControls` 的正規化／索引映射規則。理由：

1. e2e 驗證的標的是「使用者看到的介面狀態」，DOM 控件值就是該狀態本身，不需要一層額外映射去「猜」DOM 應該長什麼樣。
2. 複刻映射規則（`config.rowSeparators[real index] ?? null` → `'inherit'`/`'preset:X'`/`'custom'`）等於在 e2e 腳本裡重寫一份 `refreshRowSeparatorControls` 的邏輯，兩處會漂移（main.ts 若日後調整正規化規則，e2e 腳本要同步改，但沒有型別系統或測試會提醒）。
3. 讀 DOM 值不需要額外一次 `JSON.parse(localStorage...)`＋索引運算，evaluate 表達式更短。

代價：若 DOM 控件本身有 bug（值與實際 config 不同步），本快照驗不出來——但此風險已由 `row-separator-control.dom.test.ts`（既有測試，T1.7 交付）覆蓋，不需 e2e 重複把關。
