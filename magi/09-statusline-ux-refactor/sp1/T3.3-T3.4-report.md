# T3.3＋T3.4 — 目錄項 draggable＋來源感知冪等清理／播報語意（origin 參數＋checkbox 落列播報）

## T3.3 定案

**單一冪等清理出口** `endDragCleanup()`（`main.ts`，緊接 `clearDropGap` 之後）：
取代原本散落於 dragend＋5 個 drop handler（li／gap placeholder／列容器空白處／
暫存列，跨中欄與目錄兩來源）各自重複的六步驟（`draggingId`／`dragOrigin`／
`dragSource` 歸零、opacity 復原、`clearDropGap`、rAF 取消、`body` class 移除）。

**來源感知**：新增模組狀態 `dragSource: 'row' | 'catalog' | null`，於 `wireDragAndDrop`
（中欄）dragstart 設 `'row'`、新 `wireCatalogDragAndDrop`（目錄）dragstart 設
`'catalog'`。`endDragCleanup` 依此分派 opacity 復原節點——`'catalog'` 查
`catalogItemElements`、其餘查 `rowElements`（同 id 在兩個 Map 存放不同節點，
清錯 Map 會清錯節點，07 DRIFT 舊項在此被本任務正當化合流）。

**目錄項 dragstart**（`wireCatalogDragAndDrop`）：checkbox 命中區豁免——複用
中欄既有 `input, select, button, textarea, [role="spinbutton"]` 選擇器，`event.target`
落在其中即 `preventDefault()` 放棄拖曳，讓點選勾取照常運作。目錄項**不**接自身
dragover／drop——落點側既有 handler（li／gap／列容器空白處／暫存列）皆只依賴
模組層級 `draggingId`，不分辨來源；`commitSegmentMove` 依 `movedSeg.enabled`
自動分派停用段（enable-into-target，T3.2 既有）或已啟用段（原移動路徑），
「已啟用目錄項被拖入＝退化為純 move」由此自動分派天然達成，未寫任何額外
if 分支。

**時序取捨（明記）**：5 個 drop handler 原本把 rAF 取消／body class 移除
留給隨後保證觸發的 `dragend` 收尾，本任務合流後這兩步改在 **drop 當下**
即執行（`endDragCleanup` 內聯，不分派）。drop→dragend 通常同一輪任務內
發生，肉眼不可辨；更早收斂視覺無副作用，換得單一出口好處更大。

## T3.4 定案

`performCrossRowMove` 新增第四參數 `origin: 'move' | 'catalog-add' = 'move'`
（預設值使既有全部呼叫點——中欄拖曳／select 指派——零改動）；播報改經
新函式 `announceSegmentLanded(origin, label, info)`：`'move'` 原樣呼叫既有
`formatMoveAnnouncement`（row-groups.ts，禁改）；`'catalog-add'` 為本任務新增
的「已加入」模板，與 `formatMoveAnnouncement` 並列集中於同一函式（G5 字串表
單一落點，M5 前僅為集中常數、非完整 i18n）。`commitEnableIntoTarget`
（T3.2 既有）改傳 `'catalog-add'`。

**checkbox 啟用分支落列播報**（`setSegmentEnabled` 啟用分支，先前完全不播報）：
`commitConfig`／`syncFgOverrideDisabled` 之後、回焦之前，以 `computeRowGroups`
查詢 clamp 落點所在列的 position／rowSize，`slotIndexOfRealRow` 映射視覺顯示
編號，呼叫 `announceSegmentLanded('catalog-add', …)`——checkbox 勾選語意上
同為「把段加入某列」而非移動既有段，故與目錄拖曳啟用共用同一模板。停用
分支（`!enabled`）維持既有零播報不變。

**顯示編號驗證**：新增 jsdom 案覆蓋 BACKLOG:37「clamp 落點的 row 值與視覺
顯示編號不符」——構造 3 段合併成中間 pending 列（`rowSlots=[real,pending,real]`）
後，越界 row 值 clamp 落入既有真實列（real index 1），正確播報「第 3 列」
（該真實列的 slot 位置＋1）而非誤用 clamp 後 row 值直接 +1 的「第 2 列」；
測試已驗證此為程式實際行為，非手算猜測。

## 交接備忘（T3.5：data-testid 上錨＋e2e 改造）

- 目錄項／中欄段列的 `data-segment-id` 沿用既有慣例，尚未上 `data-testid`；
  T3.5 應在目錄項上補穩定錨點（同中欄段列同一慣例）。
- 真實原生拖曳（游標／`dataTransfer` 實際承載、跨瀏覽器 `dragover` 節流）
  未被本任務的 jsdom 案覆蓋——jsdom 無 `DragEvent` 建構子，本檔以
  `MouseEvent(type, …)` 手工 dispatch 模擬邏輯層（`event.target`／
  `event.dataTransfer?.…`／`event.clientY` 皆對 MouseEvent 相容或有 optional
  chaining 防禦），真正原生行為驗證需歸 T3.5／T6.1 e2e（CDP，本機人工 gate）。
- e2e 既有 5 案序數斷言若比對 i18n 可見文字（如「第 N 列」），T3.4 新增的
  「已加入」模板亦需一併改走 `data-row-index` 序數屬性，見 PLAN Spec deltas
  「e2e selector 一律走錨點、斷言不得依賴 i18n 可見文字」。
