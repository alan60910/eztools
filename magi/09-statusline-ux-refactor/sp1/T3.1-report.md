## 定案簽章

```ts
export function markSegmentEnabledDeferred(id: string): SegmentConfig | undefined
```

位置：`tools/statusline-builder/main.ts`，緊接於既有 `setSegmentEnabled`
（現行 main.ts:964-1015，PLAN 委派文中的 910-954 為 M1 T1.7 後的行號位移，
已依「開工先讀現檔」核實）之後。

## 關鍵決策

1. **獨立函式，非 `setSegmentEnabled` 疊加 options 物件**：委派文允許兩種
   介面形（第三參數 options 或獨立函式），選獨立函式的理由——defer 模式
   語意上「僅支援啟用方向」，若疊加在 `setSegmentEnabled(id, enabled,
   preventScroll)` 上以第四參數 `defer` 表達，簽章上仍收得到
   `enabled=false, defer=true` 這個無意義組合，需額外註解＋執行期斷言
   把關；獨立函式從根本不收 `enabled` 參數，該組合在型別層面就不存在，
   零額外把關成本。
2. **defer 路徑只做一件事**：`seg.enabled = true`，其餘全部略過——不
   `clampReenableRow`、不動 `rowSlots`／`config.rowSeparators`、不
   `syncSegmentEnabledUi`、不 `commitConfig`、不 `syncFgOverrideDisabled`、
   不回焦。row/slots 落點留給 T3.2 的 target 決策，避免「先 clamp 進舊列
   、再搬到新列」的中間態（PLAN C1 明文禁止）。
3. **冪等**：對已啟用段呼叫是安全的 no-op 疊寫（`seg.enabled = true` 疊加
   一次仍是 `true`），呼叫端（T3.2）毋須自行判斷目標段目前是否已啟用。
4. **回傳查得的 `SegmentConfig` 物件參照**（非拷貝，同檔既有「直接 mutate
   既有物件參照」慣例）：一是供 T3.2 直接取得同一參照續寫 `.row`／其他
   欄位而不必再查一次 `segmentConfigById`；二是供測試白盒檢視 mutate 後
   狀態（`.enabled`／`.row`），因 main.ts 過去不匯出任何符號、UI 尚未接
   線前無其他管道觀察內部狀態變化。查無該 id 回傳 `undefined`（防禦，
   理論上不會發生）。
5. **T3.2 介面備忘**：`commitSegmentMove` 串接時直接呼叫
   `markSegmentEnabledDeferred(movedId)` 取代目前該函式對停用段完全不處理
   的空白（現行 `commitSegmentMove` 尚未涵蓋「拖入停用段」情境，屬 T3.2
   範圍）；**唯一一次** commit 前後仍須補跑 `syncSegmentEnabledUi`＋
   `syncFgOverrideDisabled`（否則拖入啟用中的 powerline+bar 百分比段會
   重演 I4b），此二函式呼叫點與既有 `setSegmentEnabled` 內順序一致，可
   直接比照抄錄呼叫序。
