## 關鍵決策

**輸出形定案**：`computeSegmentFieldDefaults(id: string, descriptor: SegmentDescriptor): SegmentFieldDefaults`，
`SegmentFieldDefaults = Readonly<Record<SegmentFieldKey, { applicable: boolean; defaultLabel: string }>>`，
`SegmentFieldKey = 'row'|'icon'|'prefix'|'variant'|'color'|'fgOverride'|'threshold'|'bar'`
（八欄位鍵名直接對齊 `SegmentConfig` 欄名，`fgOverride` 例外沿用該欄本名）。
`applicable: false` 時 `defaultLabel` 為空字串——呼叫端（T2.2）須先判
`applicable` 決定是否渲染整組欄位（比照 main.ts `buildSegmentRow` 現行
variant/threshold/bar 三欄「不適用即整組 `remove()`」慣例）。

**輸入面：吃 `descriptor` 而非自行查表**——brief 原文「輸入 segment id
（＋descriptor 查表）」有兩種讀法：(a) 函式內部 import `segments.ts` 的
`DESCRIPTORS_BY_ID` 自行查表，或 (b) 呼叫端傳入已查好的 `descriptor`。
選 (b)：T2.2 的 `buildSegmentRow(seg, descriptor)`（main.ts:1091）本就同時
持有兩者，直接傳遞零額外成本；且讓本模組不必依賴 `segments.ts` 的真實
目錄（僅 `import type`，零執行期依賴），與 `config.ts` 檔頭「segment 目錄
以 SegmentCatalog 注入…本模組不依賴之」的既有解耦慣例同構。測試因此可用
`fakeDescriptor` 工廠建構最小合法 descriptor（比照 `config.test.ts` 假
`CATALOG` 慣例），不受真 30 段目錄變動牽動。

**適用性（applicable）判準**：
- `row`／`icon`／`prefix`／`color`／`fgOverride` 五欄恆適用（每段皆有）——
  `fgOverride` 恆真的依據是 main.ts:1245「T5.1：全段皆註冊（fg-mount 對
  全段存在，僅 CSS 依 mode 顯隱）」，適用性與段身分無關、僅與目前 mode
  的顯示態有關，本 helper 不判斷 mode。
- `variant` 適用 = `descriptor.variants !== undefined`。
- `threshold`／`bar` 適用 = `descriptor.category === 'percentage'`——與
  `segments.ts` 導出 `barEligibleIds` 的判準同源（該檔「T3.3」節：
  `barEligibleIds＝category==='percentage'`），故不需注入 catalog、只讀
  `descriptor.category` 即可，省了一份 catalog 依賴。

**預設值來源與「單一定義」保證**：`computeSegmentFieldDefaults` 與
`isSegmentFieldAtDefault` 皆先呼叫 `defaultSegmentConfig(id)` 取得基準值
（`icon`／`color`／`prefix`／`row`／`fgOverride`／`threshold`／`bar` 皆從
該物件讀取，非本檔另編硬值），只有 `variant` 的預設（`descriptor.
variants[0]`）與 `threshold`／`bar` 的「是否適用」判準需 descriptor 後備
——避免預設值定義在兩處漂移（PLAN D2 明訂的兩個權威來源）。

**`isSegmentFieldAtDefault` 簽章補上 `descriptor` 參數**：brief 原文
「輸入 SegmentConfig 與欄位 key」未提 descriptor，但 `variant` 欄的預設
（`descriptor.variants[0]`）若不傳 descriptor 無法正確比較——採
`(seg: SegmentConfig, descriptor: SegmentDescriptor, key: SegmentFieldKey): boolean`。
T2.2 呼叫點同樣手握兩者，零額外成本。欄位不適用時（如無 variants 之段的
`variant`）回傳 `true`（語意：沒有可偏離預設的欄位＝視同仍在預設態），
但呼叫端仍應先判 `applicable` 才決定是否渲染。

**顏色比較**：`SegmentColor`（`color` 欄，含 `auto` 第四態）與 `ColorSpec`
（`fgOverride` 欄，三態封閉）結構相容（`SegmentColor = ColorSpec |
{kind:'auto'}`），故寫一個 `segmentColorEqual` 服務兩欄，而非各自手比對；
`undefined` 視為獨立態（`fgOverride` 缺欄 ≠ `{kind:'default'}`，儲存語意
不同，即使 main.ts:1238 兩者在 picker 上顯示相同）。

**顯示字串**：集中於檔案頂部常數（M5 i18n 候選，PLAN D2 原文要求）。
`VARIANT_LABELS` 為 main.ts:122-128 對照表的**複製值、不 import
main.ts**——該檔頂層即跑 DOM query，node 測試 import 會炸；已於常數旁
註明「與 main.ts:122-128 對照表一致，M5 收斂單一來源」供下游 M5 任務
接手時定位雙寫點。`終端預設`／`自動配色` 等文字取自既有 UI 用語
（index.html:852「終端預設」radio 可及名稱）以維持一致性，非自創。

**`colorDisplayLabel` 導出**：窮盡處理 `SegmentColor` 四態（含 `ansi256`
經 `ansi256SwatchName` 鏡像、`truecolor` 原樣 hex），雖然目前
`defaultSegmentConfig` 恆回 `{kind:'default'}`（只會走 'default' 分支），
仍窮盡實作並測試四態——供 T2.2 之後若需顯示「現值」色彩描述（非僅預設）
時直接重用，避免另編一份 switch。
