## 關鍵決策

1. **「跳至產出腳本」只 `focus()`、不開 dialog**：依團隊調度指示的具體
   語意（「聚焦鈕，不自動開 dialog——skip 目的是『到達控制項』非
   『觸發』」）採用，未反提其他方案；此舉也避免鍵盤使用者被迫每次
   skip 都跳出一個 modal dialog（fallback 非模態路徑下 dialog 開啟會
   搬走文件流焦點語意），保留使用者自行決定是否開啟的控制權。
2. **href 改指鈕 id（`#output-dialog-open`）而非 `href="#"`**：兩者
   task brief 皆可接受，選前者理由——`<button>` 元素本身可作為錨點
   目標（有 `id`），無 JS 環境下原生錨點跳轉仍會捲動至該鈕（雖不一定
   奪取焦點，視瀏覽器實作），比 `href="#"`（滾到頁首、語意空白）更貼近
   「跳至產出腳本」原意，屬糙但有意義的漸進增強備援。
3. **`skipToOutputEl` 走 `data-testid` 屬性選擇器、不新增專屬 id**：
   沿用既有 `[data-testid="..."]` 慣例（`queryOne` 已支援任意
   selector），避免為單一連結新增一個僅測試用的 id、維持與 SPEC
   Conventions「e2e 穩定錨點走 `data-testid`」精神一致（雖本節點目前
   只有 dom.test 引用，未進 e2e）。
4. **`wireSkipToOutput()` 呼叫點置於 `wireGlobalControls()` 之後、
   `wirePendingRowButton()` 之前**：純接線先後順序無功能性依賴（`focus()`
   為原生 DOM 方法，不要求 `wireOutputDialog()` 已跑過），選此位置是
   因 skip-nav 屬「全域導覽控件」而非「輸出 dialog 專屬邏輯」，與
   `wireGlobalControls()` 語意相鄰、視覺上易於下次維護者定位。
5. **「跳至預覽」與「跳至已選擇」刻意不加 `data-testid`**：僅「跳至
   產出腳本」的行為本 task 新增／需要穩定測試錨點；另兩者維持既有
   `href="#id"` 選擇器測試（`nav.skip-nav a[href="..."]`），避免無謂
   擴大變動面（brief 亦僅要求「跳至產出腳本」新語意與「跳至預覽」落點
   確認，未要求全面加 testid）。
6. **`#preview-section` 節點自身註解的過期字句一併修正**（非 dom.test
   殘留，但屬「既有案修」精神延伸）：該註解明確聲稱「跳至預覽」目標
   帶 `tabindex="-1"`，與 T4.1 起實際值 `"0"` 不符，且行文提及「語意
   改造留給 T4.3」——本 task 為 T4.3 本尊，理應更新此處使其不再誤導
   下一位讀者；改動範圍限於註解文字，無 DOM／邏輯變動，不影響任何
   既有測試。
