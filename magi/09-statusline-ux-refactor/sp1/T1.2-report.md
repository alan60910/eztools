## 關鍵決策

**API 簽章定案**（三函式，皆純函式、回傳新陣列、不 mutate 輸入）：

```ts
export type RowSeparator = SeparatorConfig | null

export function removeRealAt(seps: readonly RowSeparator[], realIndex: number): RowSeparator[]
export function insertNullAtReal(seps: readonly RowSeparator[], realIndex: number): RowSeparator[]
export function padToLength(seps: readonly RowSeparator[], targetLength: number): RowSeparator[]
```

- **座標系**：兩個變異函式（`removeRealAt`／`insertNullAtReal`）**只收
  real index**（第 k 個 real slot＝第 k 個渲染列），不收 slot index——
  呼叫端（T1.7）自行用既有 `slotIndexOfRealRow`／`realIndexOfSlot`
  換算。這也是「pending-only 操作對 rowSeparators 為 no-op」的落地方式：
  本模組刻意不提供以 slot index 為座標的入口，`removePendingRow`／
  `appendPendingSlot` 兩個 pending-only 變異點因此**結構上不可能**呼叫到
  本模組任何函式，不需額外守衛程式碼。
- **removeRealAt**：對應真實列刪除（`performRowDeletion`）與清空壓縮
  （`setSegmentEnabled` drain／`commitSegmentMove` 之 `srcDrains`，皆對應
  row-slots.ts 的 `convertRealToPending`）——該列覆寫連同其位置一併移除
  （`filter` 語意），其後覆寫前移一格。越界（防禦）視為 no-op、回傳淺
  拷貝，不拋錯（比照 row-slots.ts 防禦慣例）。
- **insertNullAtReal**：對應 `commitSegmentMove` 之 pending consume
  物化（對應 row-slots.ts 的 `consumePendingSlot`）——於該啟用列位
  splice 入 `null`（新列本身無覆寫），其後覆寫同步後移。`realIndex`
  以 `Math.max(0, Math.min(realIndex, seps.length))` clamp，允許等於
  `seps.length`（末端追加）與防禦負值/超界。
- **padToLength**：防禦性長度對齊 helper，**僅處理「不足」**（尾端補
  `null`）——已達標或過長皆 no-op。刻意不實作「過長修剪」：PLAN A-2 已
  明訂序列化前修剪尾端 `null` 委由 config 端既有清洗邏輯負責，本模組
  不重複實作（brief 原話「尾端 null 修剪可委回 config 清洗，不重複
  實作」）。
- **型別**：`import type { SeparatorConfig } from './config.js'`
  （type-only），未觸碰 config.ts 本體（T1.1 並行改動中）。

**測試設計**：
- 三函式各自基本案（頭／中／尾／null 值／不 mutate 輸入／越界防禦）。
- PLAN Verification 明列的「reindex 三型正反案」逐一具名對應：
  - 型 1 刪中間列（上方留、下方降位）
  - 型 2 空列壓縮（該列覆寫消滅，斷言 `not.toContainEqual` 不殘留/外洩）
  - 型 3 移列 swap（覆寫跟列走）——以 `removeRealAt`（來源列耗盡）
    ＋`insertNullAtReal`（落點物化）兩步組合模擬 `commitSegmentMove`
    的真實呼叫序列，斷言未涉及的列覆寫全程只認自己的值。
  - 另補 pending 物化案（PLAN A-3 原句對應的獨立具體例子）。
- **組合矩陣 spike 案**：窮舉初始 3 列、深度 ≤4 的所有 `remove`／
  `insertNull` 混合操作序列（用一支 `.scratch-count.mjs` 量測腳本
  〔用後即刪，未留痕〕先量出節點數＝4273，屬「小規模」，執行僅
  ~260ms 測試時間內完成）。獨立維護一條 `identity`（列身分）陣列——以
  **內建** `Array.prototype.splice`（非重用待測程式碼）作為獨立於實作
  的 ground truth，每次遞迴皆斷言：`identity[i]` 為數字 k 時
  `seps[i]` 必須等於 `tagFor(k)`；`identity[i]` 為 `null` 時 `seps[i]`
  必為 `null`；任何已從 `identity` 消失的原始列 id，其覆寫值不得殘留於
  `seps` 任何位置（防止實作 bug 把覆寫錯位搬移或重複）。`assertionCount`
  斷言恰為 4273，防止窮舉邏輯本身跑偏（如漏掉末端插入索引）而悄悄縮小
  覆蓋面。
