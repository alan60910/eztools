## 關鍵決策

1. **新增兩個純函式 helper**（置於 `groupByRow` 之後、`emitBash` 主體之
   前，§「逐列分隔符解析」小節）：
   - `rowSeparatorValue(config, rowIndex)`：`(config.rowSeparators?.[rowIndex]
     ?? config.separator).value`。`rowIndex` 直接吃 `groupByRow` 分組序
     （呼叫端傳迴圈變數 `r`），與 PLAN A-1「索引基準＝啟用列位」的契約
     同基準，**不需**額外映射（與 resolve 的「存活列→啟用位」映射不同，
     那是 T1.3 的事——emit 期只依 config 決定「有幾列、每列覆寫什麼」）。
   - `hasAnyRowSeparatorOverride(config, rowCount)`：`rowSeparators` 全
     `null`／缺席／越界 → `false`，這是 no-override fast path 的唯一判準。
2. **SEP 宣告三分支**（原 `emit-bash.ts:932` 單一 `SEP=` 行拆為條件式）：
   - `rowGroups.length <= 1`（單列或空鏈）：恆宣告 bare `SEP=`，值改綁
     `rowSeparatorValue(config, 0)`——即「單列路徑 SEP 綁列 0 覆寫」
     （A-4），無覆寫時即 `config.separator.value`，與改動前逐位元組相同。
   - 多列＋無覆寫：沿用改動前單一 `SEP=` 宣告（fast path，byte-exact）。
   - 多列＋有覆寫：逐列 `SEP_${r}=`（r＝啟用列位，即 `rowSuffix` 的
     `_${r}` 同一數值）；**未覆寫的列亦宣告**、退全域值，確保 `joinPlain`
     可統一以 `SEP${rowSuffix}` 引用，不需額外「該列有無覆寫」判斷。
3. **`joinPlain` 改收 `sepVar` 參數（PLAN 提供的兩選項之一：「或改收
   參數」），未採「純由 rowSuffix 推導」**：因為多列＋無覆寫時所有列仍
   須引用同一個 bare `SEP`（`rowSuffix` 非空但變數名不該跟著加尾碼），
   若直接推導 `SEP${rowSuffix}` 會在「多列＋無覆寫」情境誤產生
   `SEP_0`／`SEP_1` 引用（而宣告端仍是單一 `SEP=`），造成未定義變數。
   故呼叫端顯式決定 `sepVar`：單列路徑恆傳 `'SEP'`；多列路徑依
   `hasRowSepOverride` 二選一傳 `'SEP'`（全域）或 `` `SEP${rowSuffix}` ``
   （逐列）。函式本體只做兩處字串替換（`-n` 判定與插值串接），沿用既有
   `\${${var}}` 巢狀跳脫慣例（比照既有 `bgsVar`／`textsVar` 寫法）。
4. **powerline 零觸碰**：`hasRowSepOverride` 計算式本身即
   `config.mode === 'plain' && ...`；SEP 宣告區塊、`joinPlain` 呼叫皆限
   plain 分支（powerline 走 `joinPowerline`，未曾引用過 SEP）。已補測試
   斷言 powerline＋`rowSeparators` 有值時輸出完全不含 `SEP` 字面。
5. **測試最低集 6 案落地**（新增 `describe('逐列分隔符（T1.4：emit-bash
   SEP_k 展開，結構斷言）', …)`，置於既有「單列退化」與「T4.3」describe
   之間）：
   - no-override fast path 兩案：`rowSeparators` 缺席 vs 全 `null`（多列）
     產出逐位元組相同（`toEqual`）；缺席案額外斷言腳本恰一行 `SEP='|'`
     且不含 `SEP_0`／`SEP_1`／`SEP_2`。
   - 多列＋index 1（第 2 列）覆寫 `'·'`：三列皆宣告（`SEP_0='|'`／
     `SEP_1='·'`／`SEP_2='|'`），bare `SEP=`／`"$SEP"`／`${SEP}` 完全消失，
     `joinPlain` 三列各自引用對應 `SEP_k`（含 `segstart_1` 列內獨立斷言，
     沿用 T3.1 既有精神）。
   - 單列＋列 0 覆寫：只見 `SEP='·'`，不見 `SEP_0`，join 仍是扁平 bare
     `$SEP`／`${SEP}` 引用形式。
   - custom 覆寫含單引號（`'`）：`SEP_1=''\'''`——與既有「契約 6」escaping
     案同一 `bashSingleQuote` 逸出規則（`'`→`'\''`）。
   - powerline 零觸碰驗證（見上第 4 點）。
6. **既有 golden／多列展開／單列退化 describe 全數零改動、全綠**——本次
   change 未觸及任何 `__golden__/*.sh` 檔，`git diff --stat` 亦未列出該
   目錄，符合「golden 為禁區」與「本任務只做單元層正反案」的分工邊界
   （帶覆寫的 golden fixture 屬 T1.6）。
