## 關鍵決策

1. **新增單一 helper `rowSeparatorValue(config, rowIndex)`**（置於
   `groupSegmentsByRow` 之後、`now 注入` 區塊之前）：
   `(config.rowSeparators?.[rowIndex] ?? config.separator).value`。
   `rowIndex` 直接吃呼叫端既有的「啟用列位」——單列扁平路徑固定傳 `0`、
   多列展開路徑傳 `groupSegmentsByRow` 分組陣列的迭代 index `k`——與
   PLAN A-1「`rowSeparators[i]` 對位 config 正規化後啟用列位、與
   `emit-ps1.ts groupSegmentsByRow` 分組序同基準」的契約完全對齊，
   **不需額外映射**（`rowGroups` 本就是以啟用段分組後升冪排序的
   dense 陣列，其 index 即啟用位）。
2. **僅改兩個呼叫點的入參，`joinPlain`／`separatorExpr` 函式本體零改動**：
   - 原 `joinPlain(config.separator.value, 'Segs', 'out')`（單列）
     → `joinPlain(rowSeparatorValue(config, 0), 'Segs', 'out')`。
   - 原 `joinPlain(config.separator.value, \`Segs${k}\`, \`RowOut${k}\`)`
     （多列迴圈內）→ `joinPlain(rowSeparatorValue(config, k), ...)`。
   `separatorExpr`（emit-ps1.ts:937）與 `joinPlain` 本身簽名／邏輯完全
   未觸碰——覆寫值走與全域分隔符相同的 ASCII／非 ASCII 分流展開路徑
   （傳值給它，不改它），符合任務指示「零改動」。
3. **no-override fast path 為結構性保證，非額外分支**：`rowSeparators`
   缺席時 `config.rowSeparators?.[rowIndex]` 為 `undefined`，`?? config.separator`
   即落回原全域值；全 `null` 或索引越界同理——三型皆退全域，無需寫
   「若無覆寫則走舊路徑」的顯式 if，行為與改動前逐 byte 相同（既有 30+
   支 golden 案、既有多列展開 describe 全綠即為機械證據）。
4. **測試最低集 4 案全落地**（新增 `describe('逐列分隔符覆寫（T1.5：
   joinPlain 兩呼叫點傳參）', …)`，置於既有「多列展開（T3.2）」與「端到端
   byte-exact」之間）：
   - no-override fast path 兩案：缺欄 vs 全 `null` 兩者輸出逐 byte 相同
     （`toEqual`），且與 T3.2 既有多列案同形（兩列皆用全域 `|`）。
   - 多列＋第 2 列覆寫 preset 非 ASCII `'·'`：row0 仍 `'|'`、row1 用
     `[char]0xB7`（`separatorExpr` 逐 codepoint 展開形，非原始字面）。
   - 多列＋第 2 列覆寫 custom 混 ASCII／非 ASCII `'a›b'`：row1 用
     `'a' + [char]0x203A + 'b'`（ASCII 段落單引號＋非 ASCII 逐 codepoint
     以 `+` 相接）。
   - 單列＋列 0 覆寫：確認仍走既有扁平路徑（`$Segs`／`$out`，非
     `$Segs0`／`$RowOut0`），join 用覆寫值 `[char]0xB7`、不含全域 `'|'`。
   - powerline＋`rowSeparators` 存在（含覆寫值）：輸出與無此欄完全相同
     （`toEqual`）——鎖定「僅 plain 模式生效」契約。
5. **測試撰寫小修正**：初稿一則測試標題以單引號字面內嵌未跳脫的
