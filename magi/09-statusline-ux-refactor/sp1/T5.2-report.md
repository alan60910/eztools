# T5.2 — row-groups＋row-select locale 注入

## 定案

**注入形式**：兩函式皆選填尾參 `locale: Locale = DEFAULT_LOCALE`（未收 messages 實例，理由：呼叫端最不易錯——main.ts 既有兩處呼叫點 `formatMoveAnnouncement(label, info)`／`computeRowSelectOptionOps(current, rowSlots)` 皆為兩參數呼叫，選填尾參下零改動即繼續編譯，且因預設 `DEFAULT_LOCALE`（'zh-Hant'）與既有輸出完全一致，行為零漂移）。

- `formatMoveAnnouncement(label, info, locale = DEFAULT_LOCALE)`（row-groups.ts）：內部句形改取 `t(locale).announce.move(label, info.row, info.position, info.rowSize)`，取代原本內嵌的樣板字串。
- `rowSelectOptionsForSlots(slots, locale = DEFAULT_LOCALE)`（row-select.ts）：option text 改取 `t(locale).rowSelect.rowOption(i+1)` / `rowOptionPending(i+1)`。
- `computeRowSelectOptionOps(current, slots, locale = DEFAULT_LOCALE)`（row-select.ts，任務未明訂但同檔範圍內順手補齊）：新增選填尾參，原樣轉發給內部的 `rowSelectOptionsForSlots(slots, locale)` 呼叫——否則此函式會恆用 zh-Hant 目標文字，即便呼叫端想切換語言也穿不進去，與 `rowSelectOptionsForSlots` 的注入語意不一致。main.ts 既有兩參數呼叫 `computeRowSelectOptionOps(current, rowSlots)` 不受影響。

兩檔頭 docstring 皆補一段 T5.2 i18n 注入語意說明（引用 messages.ts／T5.1，註明相容性硬約束與「實際語言穿線留待 T5.5」）。

## 同檔硬編中文句形盤點（讀檔盤點結果）

- **row-groups.ts**：除 `formatMoveAnnouncement` 內建的播報句形外，逐行掃描（含 grep 比對含中文字元的字串／樣板字面）未發現其他執行期輸出的硬編中文句形——其餘中文皆為 JSDoc 註解（不是 runtime 輸出，不需 i18n 化）。
- **row-select.ts**：同法盤點，唯一執行期硬編句形即 `rowSelectOptionsForSlots` 內的「第 N 列」／「第 N 列（新列）」模板，已改注入；其餘中文亦皆為註解。

兩檔皆無遺漏項。
