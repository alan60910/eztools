## 摘要

「產出腳本」由 T4.1 的過渡期跳轉錨鈕，正式收斂為頂帶右端單一按鈕
（`#output-dialog-open`），click 開啟原生 `<dialog id="output-dialog">`

SPEC.md:102「live region 須常駐 a11y tree」不變量），不隨產出區入 dialog。
`#settings-path` 維持在左側全域設定區未動。

## 關鍵決策

1. **`<dialog>` 取代 `<section id="output-section">`，id 改名
   `output-dialog`**：依團隊調度指示的具體命名（`<dialog id="output-
   dialog">`）採用；`output-section` 這個 id 未在 main.ts／e2e 腳本內被
   引用（已查證），僅 skip-nav 錨點與舊 dom.test 用到，兩者處理見下方
   決策 6／7。
2. **showModal 特徵偵測 fallback（`typeof el.showModal === 'function'`）
   ＋非模態 `open` 屬性退路**：jsdom（`node_modules/jsdom/lib/jsdom/
   living/nodes/HTMLDialogElement-impl.js`）只實作 `open` IDL 屬性，
   完全未實作 `showModal()`／`close()`／`close`／`cancel` 事件——本 task
   的 jsdom 案因而天然走 fallback 分支，是唯一可測路徑；真實瀏覽器下
   `showModal` 分支才會執行。完整 iOS Safari <15.4 相容矩陣裁決刻意
   留給 T4.4 spike（已在 index.html／main.ts 註解中明確標註「不逾越
   該任務範圍」），本 task 只求「不炸＋可測」的最小合理實作。
3. **`close` 事件為關閉焦點還原的唯一出口**：`closeOutputDialog()`（顯式
   「關閉」鈕／backdrop click 呼叫）與原生 `close()` 皆落到同一個
   `dialog.addEventListener('close', ...)`；fallback 分支手動
   `removeAttribute('open')` 後**顯式**派送一個 `close` 事件以維持路徑
   一致，避免「原生 close() 觸發」與「fallback 手動關閉」各自還原出不同
   行為。jsdom 測試以 `dialogEl().dispatchEvent(new Event('close'))`
   直接驅動同一段邏輯，驗證與真實瀏覽器路徑共用同一出口。
4. **新增顯式「關閉」鈕（PLAN 原文未強制要求）**：PLAN §D4 A-2 僅寫
   「Esc／backdrop 關閉沿原生」，但 fallback（非 showModal）路徑下的
   `<dialog>` 是**非模態**——Esc 鍵在非模態 dialog 上不會觸發任何原生
   關閉行為（僅 `showModal()` 開啟的模態 dialog 才有隱含 cancel-on-Esc
   語意），若舊瀏覽器只能落到 fallback 分支且無顯式關閉鈕，使用者將被
   困在 dialog 內。故本 task 主動新增一顆「關閉」鈕，與 backdrop click
   共用 `closeOutputDialog()`／`close` 事件出口，成本低（一顆按鈕＋
   一行 CSS）且補上 fallback 路徑的可用性缺口，於 index.html 該節點
   註解與此處一併記錄，供審查者知悉此為本 task 主動決策而非誤讀 PLAN。
5. **backdrop click 關閉（PLAN 標為選配）：本 task 決定實作**——判準為
   `event.target === outputDialogEl`（點擊落在 dialog padding-box／
   backdrop 本身，非任何子元素），常見模態慣例、成本低、與顯式關閉鈕
   共用同一收斂出口，故採用。
6. **`#output-status` 移至 `<main>` 開頭並補 grid-area**：沿用既有
   `#error-message`「常駐 is-empty live region、獨立跨欄置頂列」慣例
   （PLAN §D3 Rev 2 釘死該慣例於 error-message），新搬入的 `#output-
   status` 若不比照給予顯式 `grid-area`，會被 CSS grid auto-placement
   置入 `catalog`/`selected` 儲存格造成視覺重疊——本 task 新增
   `output-status` 具名列一併解決。
7. **skip-nav「跳至產出腳本」（`href="#output-section"`）本 task 刻意
   不修**：該 id 已隨 dialog 重構消失，此連結現況會變成 no-op（不再如
   T4.1 report 所述地捲動聚焦）。T4.3 的任務原文明確是把此機制整個換成
   「main.ts 顯式呼叫 `outputDialogOpenEl.focus()`」（非仍走 href 錨點
   跳轉），任何本 task 對 href target 的權宜修補都會被 T4.3 完全重寫、
   徒增變動量且無法沿用；且既有 dom.test 皆未斷言 skip-nav（已查證零
   測試涵蓋），故不修此 href 不會造成測試迴歸，只留一個已於此處明確
   記錄、T4.3 本就要處理的介面缺口。
8. **關閉鈕置於三個 output-block 之後（DOM 序最末）**：確保「開啟時聚焦
   dialog 內第一個可聚焦元素」落在 `#copy-bash`（第一份產出的複製鈕）
   而非關閉鈕本身——避免使用者開啟 dialog 後誤按 Enter/Space 立即關閉。
