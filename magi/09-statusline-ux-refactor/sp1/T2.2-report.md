## 關鍵決策

1. **選項 C 一併實作**：PLAN 允許「若判斷有風險可只做 A」，但既有
   `isSegmentFieldAtDefault` 已備妥且 `commitConfig` 是天然的單一收束點，
   風險評估為低，故一併做了。
2. **a11y 取捨**：所有提示 span 皆 `aria-hidden="true"`、不進 label
   的 accessible name——維持 SPEC「含值控件 accessible name 以
   label[for]／legend 承載」慣例不變（否則 `<label for="cwd-variant">`
   的 accessible name 會被拉長成「cwd — 顯示樣式（預設：完整路徑）」，
   對螢幕閱讀器使用者反而是雜訊：預設值是「看得到才有用」的視覺輔助
   資訊，非控件本身身分的一部分）。測試中已驗證八欄位提示皆
   `aria-hidden="true"`。
3. **同步時機選 `commitConfig`／`buildSegmentRows` 兩處收束點，不逐
   handler 掛尾**：欄位變動路徑不只「使用者改這格」一種（拖曳跨列、
   上下移鈕、閾值模板批次套用、bar 切開連動材料化 threshold 等），若逐
   handler 補呼叫必然掛一漏萬；改在 `commitConfig` 統一同步，任何路徑
   只要最終走過 `commitConfig`（現況：全部都會），淡化態就保證收斂。
   測試已驗證「開啟 bar 連帶材料化 threshold」一次互動同步翻轉兩欄的
   案例，證明此設計涵蓋跨欄位連動。
4. **color／fgOverride／threshold 三欄不掛在既有 label 上**：這三欄
   在既有 DOM 結構中本就沒有「一個 label 包住可見文字」的節點（legend
   即 accessible name 本體、disclosure 鈕文字亦同構），為避免動到
   `createColorPickerCore`（跨多處共用，含閾值 10 桶自身也呼叫
   `createColorPicker`）這種高影響面函式，改在 `buildSegmentRow` 呼叫端
   把提示掛在 mount div／toggle 鈕上，維持 `createColorPickerCore`／
   `buildThresholdEditor` 兩函式簽章與內部邏輯完全不變。
