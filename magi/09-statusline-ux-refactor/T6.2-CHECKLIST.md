## A. 逐列分隔符（G1：覆寫／繼承／powerline 灰化／存檔重載跟列走）

1. 開啟工具頁，於中欄「已選擇」區準備至少 2 列（可手動勾選左欄段落，
   或用頂部「＋ 新增一列」鈕開新列後拖入／勾選段落）。
2. 找每個列群組標題列的「列分隔符」下拉（列群組 header 內，
   `data-testid="row-separator-preset"`），確認初始值為「（全域）」。
3. 將其中一列的下拉改為 custom，輸入一個新符號（例如 `;`），觀察頂帶
   預覽該列的分隔符即時變為 `;`，其他列不受影響。
4. 於全域控制區把「分隔符」欄位改成另一個新值，確認：仍顯示「（全域）」
   的列跟著變成新全域值；剛才已覆寫該列維持 `;` 不受全域改動影響
   （覆寫語意優先於全域）。
5. 切到「Powerline」模式，確認每列的「列分隔符」下拉整組灰化（不可
   操作）——Powerline 無分隔符語意。
6. 切回「純文字」模式，確認剛才的覆寫值（`;`）原樣恢復，未被 Powerline
   切換清空或重置。
7. 按 F5 重新整理頁面（測存檔重新載入），確認：逐列覆寫值原樣保留、且
   覆寫仍跟著你眼見的同一列（若重整前有做過刪列／搬移列的操作，覆寫
   應隨列移動，不會錯位到別列）。

## B. 預設值標示（G2：八欄位＋淡化）

1. 於中欄任一已啟用段的控件列，展開／檢視其編輯欄位。
2. 逐一確認以下 8 個欄位旁皆有「（預設：X）」文字提示：**列位、顯示
   文字、前綴、顯示樣式、顏色、fg 覆寫、閾值、bar**。
3. 保持欄位為預設值時，觀察提示文字呈現**淡化**樣式（不搶眼、opacity
   偏低）。
4. 任意挑 3–4 個欄位改成非預設值（例如換顯示樣式、換顏色、輸入自訂
   前綴），確認對應提示的淡化樣式消失（變回正常視覺權重），文字內容
   仍是「（預設：原本的預設值）」不變（提示的是預設值本身，不是目前
   值）。
5. 將剛才改動的欄位還原回預設值，確認淡化樣式恢復。

## C. 拖移入列（G3：拖入指定列／checkbox 落列播報顯示編號／已啟用項退化 move）

1. 左欄目錄找一個**未啟用**段，用滑鼠拖曳到中欄某個既有列群組容器內
   放開。
2. 確認：該段出現在目標列的對應位置；左欄該項變灰化「已加入」狀態；
   畫面上（或用 DevTools 檢查常駐 live region `#global-live-status`）
   出現「〈段名〉已加入第 N 列第 M 位（共 K）」播報文字——**N 為你眼見
   的顯示列號**，不是內部序號。
3. 若畫面有暫存空列（pending row，可先點頂部「＋ 新增一列」開一個），
   拖一個目錄段到該暫存列，確認落位正確、播報同樣採顯示編號。
4. 對一個**已啟用**（左欄已灰化「已加入」）的段，從左欄再次拖曳到另一

## F. 行動版（390×844 目視）

> 背景（如實揭露，非新發現）：`PLAN.md` §D4 A-1 驗收措辭已依 T4.4 spike
> 實測結果修訂——原「頂帶下方至少一個完整列群組可見」經實測**結構性
> 不可達**（單段編輯列 428–520px、雙段列群組 983px，任何行動裝置視窗
> 高度皆無法容納完整列群組），故改為以下較寬鬆但仍有意義的條件。
> micro-fix-2 已就此條件做過一輪視覺序調整（CSS order，行動版把「已
> 選擇」欄提前於「目錄」欄），390×844 下已選擇欄頂端可見，但**已知
> 殘留**：首個列群組標題文字仍可能低於摺線 38–154px（即需再往下捲一點
> 才看到列群組標題本身，不是完全看不到已選擇欄）；375×667 這個更窄
> 尺寸下已選擇欄頂端落在約 716px，超出視窗 667px（該尺寸未達標，390×
> 844 為主要驗收尺寸）。

3. 目視確認頂帶高度未超過視窗高度的 40%（390×844 下 40dvh ≈ 338px；
   spike 實測值為 31.5%，屬合格範圍內側）。
4. 捲動頁面，確認頂帶正下方**立即**可見「已選擇」欄的起始——列群組
   標題文字＋該列第一個段的控件（至少開頭部分露出即可，**不要求**整
   個列群組完整可見）。
5. 對照上方「背景」段的已知殘留：若你實測發現列群組標題仍需再往下捲
   一段才看到（大約 38–154px 的落差），這是**已記錄的既有限制**，不算

   件事。若你認為這個殘留體感上不可接受（例如覺得「已選擇欄看起來像
   是空的、要多滑一下才確定有內容」），請在異常回報欄註明，將評估另開
   micro-fix-3（把「已選擇」欄在 DOM 文件序上真正提前，取代目前純視覺
   層的 CSS order 做法，同時可修掉 CSS order 造成的 Tab／SR 走訪順序
