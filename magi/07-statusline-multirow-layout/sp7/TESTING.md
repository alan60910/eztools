# S7 spike 實測步驟清單

任務：T5.1（見 `../TASKS.md`；PLAN 對應 §Spikes「S7. `<option>` 原地更新的
焦點／選取保存」與 D2「列選擇 UI」段）。

本檔只列「怎麼測」與「測什麼」；**結果一律記錄到 `RESULTS.md`，本檔不含任何
實測數據**。

材料：`repro.html`（本目錄，自足單檔，雙擊即可用瀏覽器開啟，無需伺服器／建置）。

---

## 0. 背景／要驗證的兩個核心問題

「從空白建 7 列」流程每加一列＝全體啟用段「顯示於第 N 列」`<select>` 刷新
一次，刷新方式是**更新既有 `<option>` 節點**（文字）＋在「新增一列」選項前
插入一個新 option，**不重建 `<select>` 或整批 `replaceChildren`**。要驗證這個
更新路徑在三瀏覽器下是否安全：

1. **非目標 select 更新**：使用者聚焦 select A（可能已展開下拉、用方向鍵
   移動反白、尚未按 Enter）時，程式對 select B／C 做原地更新——A 的焦點／
   下拉開啟狀態／反白位置是否受影響？頁面或容器是否跳捲動？
2. **目標 select 自身更新**：select A 目前選取第 k 項；程式原地更新 A 的
   全部 option 文字（value 不變）＋插入一個新 option——A 的顯示值
   （`selectedIndex`／`value`）是否仍對應原選取（不漂移）？若焦點正在 A
   上操作方向鍵，行為是否正常？

`repro.html` 的三個 select（段 A／B／C）初始選取值刻意不同（A=第1列，
B=第2列，C=第3列），方便肉眼核對「更新後是否仍對應原選取」。「新增一列」
按鈕與「自動連續更新」toggle 會**同時**更新全部三個 select（模擬實際 UI
「全體啟用段 select 一次刷新」），因此同一組操作既可測「未被聚焦的 select」
（問題 1），也可測「被聚焦的那個 select 本身」（問題 2）——差別只在於測試時
你選擇聚焦哪一個。

## 1. 開啟方式

在檔案總管雙擊 `repro.html`（或用瀏覽器「開啟檔案」），依序在
**Chrome、Edge、Firefox** 三個瀏覽器各開一次，逐一走完下列 §2／§3 全部步驟。

開始前先把瀏覽器視窗捲動到「操作區」置中位置（讓上方 filler 與下方 filler
都還留有可見的捲動空間），方便肉眼判斷「是否跳捲動」。

---

## 2. 問題 1 操作腳本：非目標 select 更新

對每個瀏覽器執行：

1. **滑鼠聚焦，不開下拉**：點擊 select B（只聚焦，不點開下拉選單）。確認
   「事件記錄」面板出現 `select-B: focus`。
2. 點擊「新增一列」按鈕一次。記錄：
   - select B 狀態列的 `focused` 欄位是否仍為「是」（焦點沒被搬走）？
   - 頁面／`select-container` 容器是否有跳動或捲動位置改變（比對按鈕前後
     `window.scrollY` 與「容器 scrollTop」數值，以及肉眼觀察）？
   - select B 顯示的 `selectedIndex`／`value`／`text` 是否仍是原本的
     「第 2 列」？
3. **鍵盤聚焦＋展開下拉＋方向鍵移動、不提交**：用 Tab 鍵（或點擊後用鍵盤）
   把焦點移到 select A。按 Enter／空白鍵／Alt+↓（依瀏覽器慣例）展開下拉、
   用方向鍵（↓）移動反白到「第 2 列」或更後面的項目，**先不要按 Enter、
   不要點擊其他地方**。此時切換視窗焦點（例如用滑鼠點擊「新增一列」
   按鈕——這本身就是一次「使用者操作方向鍵移動中途、外部觸發了更新」的
   真實情境）。記錄：
   - select A 的下拉選單是否仍展開／自動關閉？反白位置是否還在你移到的
     位置（肉眼看下拉內容）？
   - select A 的焦點欄位（`focused`）與 `document.activeElement` 是否仍是
     A（若下拉被點擊按鈕的動作關閉，這是預期的一部分——重點記錄「除了
     你自己主動的操作外，A 有沒有被程式的 option 更新動作額外搬走焦點或
     跳位」）？
   - 頁面／容器是否跳捲動？
4. **完全不操作、觀察自動更新**：點擊聚焦某個 select（例如 C，只聚焦不展開
   下拉），開啟「自動連續更新」toggle，放著讓它自動觸發 3～5 次（約
   2.5～4 秒）都不要碰鍵盤滑鼠。記錄：
   - 事件記錄面板這段期間是否出現非你主動觸發的 `blur`／`focus`（代表焦點
     被程式搬走又搬回，或搬到別處）？
   - C 的 `focused` 欄位全程是否維持「是」？
   - 關閉 toggle。
5. 把上述觀察填入 `RESULTS.md`「問題 1」欄。

## 3. 問題 2 操作腳本：目標 select 自身更新（選取保存）

對每個瀏覽器執行（可接續 §2，或先點「重置頁面」回到初始狀態再開始）：

1. **不聚焦任何 select**，直接連續點擊「新增一列」5 次。記錄：三個 select
   的 `selectedIndex`／`value`／`text` 是否仍分別對應原本的「第 1 列」／
   「第 2 列」／「第 3 列」（未因新增了 5 個 option 而發生漂移）？
2. **聚焦目標 select 本身（不展開下拉）**：點擊聚焦 select A（目前值「第 1
   列」）。連續點擊「新增一列」5 次。記錄：
   - A 的 `selectedIndex`／`value` 是否仍是「第 1 列」對應的值？
   - A 的 `focused` 欄位是否全程維持「是」（它是被更新的 select 本身，
     理論上更新不該搬走它自己的焦點）？
3. **展開下拉、方向鍵移動中途被更新，之後提交**：聚焦 A，展開下拉，用
   方向鍵移動反白到某個新選項（例如往下移 2 格），**不提交**，點擊「新增
   一列」按鈕觸發一次更新（下拉可能因焦點切換到按鈕而關閉——這是預期
   現象，正常記錄）。接著重新聚焦回 A、展開下拉、用方向鍵移動並這次按
   **Enter** 提交。記錄：
   - 提交後 A 的 `selectedIndex`／`value`／`text` 是否正確對應你最後選定
     的那一項（而非被更新過程打亂、選到不相干的項目或維持舊值不變）？
4. **邊界情境：反白正停在「新增一列」選項上時被更新**：聚焦 A，展開下拉，
   用方向鍵移動反白到最後一項「新增一列」（不提交）。觸發一次「新增一列」
   按鈕（此更新會在「新增一列」選項**之前**插入一個新 option，把「新增
   一列」往後推一格）。記錄：
   - 反白視覺位置是否仍停在「新增一列」文字上？還是因為前面插入了新
     option 而反白位置往後跳一格、或反白位置沒動但底下的項目內容變了？
5. 把上述觀察填入 `RESULTS.md`「問題 2」欄。

## 補記（2026-07-11 協調者修訂）：第三種觸發方式

初版 repro 中，select 下拉裡的「新增一列」選項是**死的**（僅作插入位置錨點），
使用者實測時誤點該選項發現「不會真的新增」——已修訂：現在**在下拉中選
「新增一列」**會比照真實 UI 語意觸發全體 select 原地更新，並把**該段自動
指派到新列**（headless 驗證：選後 options+1、該 select value=新列號、其他
select 同步長出新列選項）。

這新增了一個值得觀察的情境（比按鈕觸發更貼近真實刷新路徑）：
- **變更提交的同一刻全體 select 被原地更新**——選「新增一列」提交瞬間，
  觀察：該 select 顯示值是否正確落在新列（不閃爍／不短暫顯示錯項）、
  其他 select 的選取是否不受影響、頁面是否跳捲動。
- 三瀏覽器矩陣請將此情境一併記錄（RESULTS.md 矩陣可在備註欄補充，或
  自行加一列）。

## 補記 2（2026-07-11 協調者修訂）：儀表觀察者效應修復

使用者實測發現：初始狀態先點段 A/B 再點段 C，C 的下拉會自動關閉（再點一次
正常）。根因是 repro 自身儀表的觀察者效應——事件記錄面板原用 `max-height`，
未滿 12 行前每插一行（blur＋focus 連續兩行）就長高、把 select 容器往下推，
原生下拉遇開啟瞬間版面位移即自動關閉；且段 C 初始被容器裁掉一截，first
focus 多一次 scrollIntoView。已修：log 面板改固定高度、三個 select 初始
全部可見（容器底部惰性墊高保留捲動觀察）。

**對實測的意義**：修復後若再出現「下拉自動關閉」，即為真訊號（option 原地
更新造成），不再是儀表噪音——請照常記錄。
